# BM 자가진단 · 구조와 로직 명세

「Business Model Validation Framework」를 웹 설문형 자가진단 도구로 옮긴 결과물입니다.
방문자가 20문항에 답하면 4개 영역 점수, 최종 판정, 우선 과제, 미검증 가설을 담은 **BM 초기 검증 리포트**가 즉시 생성됩니다.

## Claude 분석 실행

1. Node.js 20.6 이상에서 프로젝트 폴더를 엽니다.
2. `.env.example`을 `.env`로 복사하고 새 키를 `ANTHROPIC_API_KEY`에 설정합니다. `.env`는 Git에서 제외됩니다.
3. `npm run start:local` 실행 후 `http://localhost:3000`에 접속합니다.

**무료 진단 시작하기**를 누르면 보라색 채팅형 설문이 시작됩니다. 20문항을 완료하면 **비즈니스 모델 분석 중** 화면을 거쳐 점수·판정과 Claude 분석을 한 리포트에서 보여줍니다. Claude 연결이 실패하면 자가진단 점수와 판정을 먼저 표시하고, 리포트에서 같은 답변으로 재시도할 수 있습니다. HTML을 파일로 직접 열면 자가진단 점수를 계산합니다. Claude 분석을 운영 서버에서 사용하려면 서버 환경변수에 키를 넣고 `npm start`로 실행합니다.

| 파일 | 역할 |
|---|---|
| `server.mjs` | HTML 제공, `GET /api/questions`와 `POST /api/report`, 기존 `POST /api/analysis` 처리 |
| `claude.mjs` | Claude 호출, 맞춤 진단 프롬프트와 응답 구조 |
| `.env.example` | 키와 모델의 환경변수 예시 |

## 2. 화면 흐름

```
[랜딩] ─ 시작 → [채팅형 기본 정보와 20문항] → [비즈니스 모델 분석 중] → [리포트 + Claude 분석]
```

| 화면 | 내용 | 다음으로 넘어가는 조건 |
|---|---|---|
| 인트로 | 헤드라인, 4영역 소개, 시작 버튼 | – |

척도: 1 전혀 아니다 · 2 아니다 · 3 보통 · 4 그렇다 · 5 매우 그렇다

| 영역 | 번호 | 문항 | 미검증 시 가설명 |
|---|---|---|---|
| **01 시장 수요** | Q1 | 목표 고객을 한 문장으로 구체적으로 말할 수 있다 | 목표 고객 정의 |

| | Q4 | 고객이 이미 돈·시간을 들여 해결하려 한다 | 고객의 해결 의지·행동 |

| | Q7 | 핵심 기능과 제공 가치를 한 줄로 말할 수 있다 | 핵심 가치 제안 |
| | Q8 | 고객 이익을 수치로 말할 수 있다 | 고객이 얻는 구체적 이익 |
| | Q9 | 보유 기술·자원·역량으로 제공할 수 있다 | 보유 역량으로 제공 가능 여부 |

| | Q13 | 경쟁사 가격·요금 구조를 비교했다 | 경쟁사 가격·요금 구조 |
| | Q14 | 경쟁사의 핵심 강점을 안다 | 경쟁사 핵심 강점 |

| | Q17 | 차별화 축이 정해져 있다 | 차별화 축 |

## 4. 채점 로직

### 4-1. 영역 점수 (0~100)
```
영역 점수 = (5문항 합계 − 5) ÷ 20 × 100   (반올림)
```
전부 1점 → 0 · 전부 3점 → 50 · 전부 5점 → 100

### 4-2. 영역 등급
| 점수 | 등급 | 색 |
|---|---|---|
| 70 이상 | 양호 (good) | 초록 |
| 40 ~ 69 | 보완 필요 (mid) | 노랑 |
| 40 미만 | 취약 (bad) | 빨강 |

### 4-3. 종합 점수
```
종합 점수 = 4개 영역 점수의 평균 (반올림)
```
종합 점수는 표시용입니다. **판정에는 쓰지 않습니다.** 평균이 높아도 한 영역이 무너지면 사업이 성립하지 않기 때문입니다.

## 5. 최종 판정 로직 (프레임워크 '최종 판단 기준' 3상태)

위에서부터 순서대로 검사하고, 처음 걸린 판정을 씁니다.

```
IF 시장 수요 < 40 OR 해결 가능성 < 40 OR 차별화 < 40
    → ❌ BM 재설계 필요
ELSE IF 4영역 모두 ≥ 70 AND Q5(수요 근거) ≥ 4 AND Q18(차별화 근거) ≥ 4
    → ✅ 초기 BM 가설 수립
ELSE
    → ⚠️ 추가 검증 필요
```

| 판정 | 프레임워크 정의 | 로직상 근거 |
|---|---|---|
| 초기 BM 가설 수립 | 네 영역이 구체적으로 정의되고 주요 가설에 근거가 존재함 | 4영역 모두 70+ 이면서 근거 문항 2개가 4점 이상 |
| 추가 검증 필요 | 사업 가능성은 있으나 핵심 가설의 근거가 부족함 | 재설계 조건엔 안 걸리지만 가설 수립 조건 미달 |
| BM 재설계 필요 | 수요, 제공 가능성 또는 고객 선택 이유에 중대한 문제 | 해당 3영역 중 하나라도 40 미만 |

> **경쟁 환경은 재설계 조건에서 뺐습니다.** 프레임워크가 '중대한 문제'로 꼽는 대상은 수요·제공 가능성·선택 이유입니다. 경쟁 분석이 부족한 것은 조사로 메울 수 있는 공백이라 '추가 검증 필요'로 처리합니다.

## 6. 우선 과제 로직 (프레임워크 '의사결정 구조')

STEP 1 → 4 순서로 훑어서 **처음으로 70점 미만인 영역**의 다음 단계를 '지금 가장 먼저 할 일'로 보여줍니다. 모두 70 이상이면 STEP 4 양호 문구(BM 가설 정리)를 보여줍니다.

| 단계 | 양호 (≥70) | 보완 필요 (40~69) | 취약 (<40) |
|---|---|---|---|
| STEP 1 시장 수요 | STEP 2로 → 해결 가능성 검토 | 추가 검증 → 고객 인터뷰 5~10명, 검색량·커뮤니티 근거 수집 | 재정의 → 목표 고객이나 문제 재정의 |
| STEP 2 해결 가능성 | STEP 3로 → 경쟁 환경 분석 | 시제품 검증 → 수작업 서비스·랜딩·MVP | 재설계 → 솔루션 범위·제공 방식 재설계 |
| STEP 3 경쟁 환경 | STEP 4로 → 차별화 검증 | 비교표 작성 → 경쟁사 3~5곳 제품·가격·강점, 리뷰 불만 | 시장 조사 → 경쟁사·대체재 목록부터 |
| STEP 4 차별화 | BM 가설 정리 → 문서화 후 소규모 판매 | 선택 이유 검증 → 광고·랜딩으로 클릭률·사전신청 측정 | 포지셔닝 재설계 → 미충족 요구에서 가치 제안 재설계 |

## 8. 리포트 구성

| 순서 | 블록 | 데이터 출처 |
|---|---|---|
| 1 | 헤더 (날짜, 아이디어) | `info.idea` |
| 2 | 판정 카드 + 종합 점수 링 | `verdict`, `total` |
| 3 | 영역별 진단 (레이더 차트 + 막대, 가장 강한·약한 영역) | `areas[]`, `strongest`, `weakest` |
| 4 | 지금 가장 먼저 할 일 | `priority` |
| 5 | 영역별 피드백과 다음 단계 | `areas[].feedback`, `areas[].next` |
| 6 | BM 초기 검증 보고서 6행 표 | `table[]` |
| 7 | 추가로 확인해야 할 가설 | `weakShown[]` |
| 8 | CTA (상담 신청 / 결과 요약 복사 / 다시 진단) | `summary`, `CTA_URL` |

### BM 초기 검증 보고서 표 (프레임워크 최종 산출물)
| 평가 영역 | 채워지는 내용 |
|---|---|
| 시장 수요 | 입력한 목표 고객 + 수요 영역 피드백 |
| 제공 가치 | 입력한 아이디어 + 해결 가능성 피드백 |
| 경쟁 환경 | 입력한 경쟁사·대체재 + 경쟁 환경 피드백 |
| 차별화 | 차별화 피드백 |
| 선택 이유 | Q20·Q18 조합 문구 (둘 다 4+ / Q20만 4+ / 그 외) |
| 미검증 가설 | 2점 이하 문항 개수 |

## 9. 사용법

### 웹페이지 그대로 쓰기
`index.html` 하나로 동작합니다. 상단 스크립트의 설정만 바꾸면 됩니다.
```js
const CTA_URL = "https://forms.gle/xxxx";  // 비우면 상담 버튼이 숨겨짐
const CTA_LABEL = "전문가와 BM 검증 상담받기";
```

### 로직만 가져다 쓰기
```js
// Node
const BM = require("./bm-logic.js");
const report = BM.buildReport(
  { idea: "1인 미용실 예약 앱", customer: "1인 원장", comp: "네이버 예약" },
  [[4,4,3,4,3], [4,4,3,4,4], [3,2,2,4,2], [3,3,2,3,3]]
);
console.log(report.verdict.label);  // "추가 검증 필요"
console.log(report.summary);
```
```html
<!-- 브라우저 -->
<script src="bm-logic.js"></script>
<script> const r = BMLogic.buildReport(info, answers); </script>
```

### 기준 조정
`bm-logic.js` 상단 `CONFIG`에서 바꿉니다.

| 키 | 기본값 | 의미 |
|---|---|---|
| `GOOD_LINE` | 70 | 양호 기준선 / 가설 수립 기준 |
| `BAD_LINE` | 40 | 취약 기준선 / 재설계 기준 |
| `WEAK_ANSWER_MAX` | 2 | 이 점수 이하면 미검증 가설 |
| `EVIDENCE_MIN` | 4 | 근거 문항 통과 점수 |
| `WEAK_LIST_LIMIT` | 8 | 리포트에 보여줄 가설 수 |

### 테스트
```
node test-bm-logic.js   → 9개 테스트 통과
```

## 10. 알려진 한계 / 확장 포인트
- **응답 저장 없음**: 현재는 브라우저 안에서만 계산합니다. 리드 수집을 하려면 리포트 생성 시점에 `buildReport()` 결과를 구글시트·DB·폼으로 전송하는 코드를 추가하세요.
- **자기평가 기반**: 점수는 응답자의 자기 인식입니다. 실제 근거 검증은 `bm-validation-report` 스킬(웹 리서치 포함)로 이어서 진행합니다.
- 이 진단은 비즈니스 모델의 성공 여부를 확정하지 않습니다. 아이디어를 **시장에서 검증 가능한 가설**로 구체화하는 도구입니다.
